Persona

badge
La Persona es la entidad base del sistema. Representa al usuario o beneficiario que solicita atención, ingresa a demanda o participa en un proceso asociado a programas de salud mental y tratamiento de drogas.
warning
Regla central: la persona debe existir una sola vez en el sistema y debe identificarse mediante datos reales. No se deben crear personas ficticias, duplicadas ni registros simulados para completar visualmente la pantalla.

Relación general del modelo

account_tree
Persona → Episodio → Etapa → Eventos → Referencias → Egreso

La Persona es el punto de inicio del flujo funcional. Desde ella se consulta si existe un episodio activo, se revisa su historial y se determina si corresponde preparar una nueva demanda.

Identificación mínima

  • RUN o identificador oficial: dato principal para búsqueda y validación.
  • Nombres: nombres registrados de la persona.
  • Apellidos: apellidos registrados de la persona.
  • Fecha de nacimiento: permite validar edad y antecedentes administrativos.
  • Sexo: dato proveniente de catálogo real cuando esté disponible.
  • Teléfono de contacto: medio principal de comunicación.
  • Correo electrónico: dato opcional cuando exista.
  • Comuna o territorio asociado: permite análisis territorial y derivación.

Información complementaria

  • Dirección: domicilio o referencia territorial disponible.
  • Previsión de salud: información previsional real desde catálogo.
  • Convenio previsional: dato asociado cuando corresponda.
  • Contacto alternativo: persona o medio de contacto adicional.
  • Observaciones administrativas: antecedentes útiles para continuidad de atención.
  • Antecedentes relevantes: información necesaria para orientar el proceso.

Búsqueda por RUN

El sistema debe permitir buscar una persona mediante RUN real, utilizando servicios existentes del backend. La búsqueda debe normalizar el RUN, evitando puntos, espacios u otros caracteres que puedan afectar la consulta.

search
Si la persona existe, se muestra su tarjeta con información real entregada por backend. Si no existe, se puede habilitar la opción de registrar persona solo cuando el backend cuente con endpoint real para dicha operación.

Cuando la persona existe

  • Se muestra la tarjeta de persona con datos reales.
  • Se habilita la consulta de episodio activo.
  • Se conserva el identificador real entregado por backend.
  • No se reemplazan datos por información local.
  • No se sobreescribe información sin acción autorizada.
  • No se genera una segunda persona para el mismo RUN.

Cuando la persona no existe

  • Se informa que no existe registro asociado al RUN consultado.
  • Se puede preparar formulario de creación solo si existe backend real habilitado.
  • No se crea persona automáticamente.
  • No se genera identificador ficticio.
  • No se continúa con episodio si no existe persona real.
  • No se deben completar campos con datos de prueba.
verified
La búsqueda de persona debe ser el primer control de seguridad funcional antes de preparar una nueva demanda. Esto evita duplicidad y permite consultar si ya existe un episodio activo.

Relación con episodio

Una persona puede tener episodios históricos, pero solo debe tener un episodio activo a la vez. Antes de preparar una nueva demanda, el sistema debe consultar si existe un episodio activo real asociado a la persona.

  • Si existe episodio activo: se muestra el episodio y se bloquea preparar nueva demanda.
  • Si no existe episodio activo: se permite preparar una nueva demanda cuando exista operación real habilitada.
  • Si falla la consulta: se debe mostrar error controlado y no inventar información.

Catálogos asociados

La creación o actualización de persona debe utilizar catálogos reales disponibles desde backend.

  • Sexo.
  • Comuna.
  • Previsión.
  • Convenio previsional.
  • Otros catálogos administrativos confirmados.
block
Mientras no estén confirmadas todas las tablas nuevas, la pantalla de persona debe consumir únicamente endpoints reales y catálogos reales. No debe completar campos con datos ficticios, mocks, arreglos locales o valores hardcodeados para simular información.
