1. Leer harness/00-index.md.

3. Identificar el módulo solicitado.
4. Leer únicamente el arnés correspondiente al módulo.
5. Si existe arnés específico para el archivo a modificar, leerlo.
6. Consultar UI, API, Negocio o Seguridad solo si corresponde.
7. Leer el código actual antes de proponer cambios.
8. No inventar reglas funcionales.
9. Si documentación, comentarios y código se contradicen,
   informar la discrepancia antes de modificar.
10. Seguir el procedimiento definido en 01-global/harness.md.
11. No ejecutar git add, commit o push sin autorización expresa.

El arnés conserva lo que necesitamos saber antes de modificar
el código. No replica ni sustituye el código fuente.
